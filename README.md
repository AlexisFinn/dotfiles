# dotfiles

My configuration files, managed with [dotbot](https://github.com/anishathalye/dotbot):
the files live in this repository and `~` only holds symlinks to them.

## How it works

- `install.conf.yaml` lists every link (`~/.config/foo` → `config/foo/`).
- `./install` creates the links. It never overwrites an existing file
  (`force: false`): move the file away first, then run it again.
- `./check` verifies that each declared link is still in place, and reports
  links into the repository that are not declared. A link that is merely
  absent is reported without failing: `./install` creates it.
- `./save [message]` runs `./check`, then commits everything and pushes.
- `./add <path>` adopts a new configuration: it moves `~/.config/<name>`,
  `~/bin/<name>` or `~/.<name>` into the repository, links it back and declares
  it in `install.conf.yaml`.

Whole directories are linked rather than single files whenever possible: a
program that saves by writing a new file and renaming it replaces a file
symlink with a regular file, and the repository copy silently goes stale.

Files generated by the tools (wpg palettes, DMS plugins and caches,
`__pycache__`) are listed in `.gitignore`.

## Installing on a new machine

Nothing here depends on a distribution: install the software below with the
system package manager (or from source when it is not packaged), then:

```sh
git clone --recursive <this repository> ~/dotfiles
cd ~/dotfiles && ./install && ./check
```

Many files contain the absolute path `/home/alexis`: keep the same user name
and clone location, or search and replace it.

Things that vary between distributions:

- `zshrc` sources zsh-autosuggestions and zsh-syntax-highlighting from
  `/usr/share/zsh-autosuggestions/` and `/usr/share/zsh-syntax-highlighting/`;
  adjust the two paths if the packages install elsewhere.
- Hyprland must be 0.57 or later (Lua configuration). Stable releases of some
  distributions ship an older version.

Configurations of software that is not installed stay declared and linked:
they are picked up as soon as the software is installed.

## Hyprland session

The configuration is `config/hypr/hyprland.lua` (`lib/` for its modules,
`scripts/` for session start and theming, `claude/` for the Claude Code
session switcher). `config/hypr/dms/*.lua` is written by DankMaterialShell
from its settings and is required at the end of `hyprland.lua`.

Software:

- [Hyprland](https://hypr.land/) 0.57+, with `hyprpm`, and
  [hyprsunset](https://github.com/hyprwm/hyprsunset) (software dimming)
- [DankMaterialShell](https://github.com/AvengeMedia/DankMaterialShell) (`dms`)
  on [Quickshell](https://quickshell.org/), with
  [matugen](https://github.com/InioX/matugen): bar, launcher, notifications,
  wallpaper, lock screen, polkit agent
- [foot](https://codeberg.org/dnkl/foot) (terminal) and luciole (file manager)
- [grim](https://sr.ht/~emersion/grim/), [slurp](https://github.com/emersion/slurp)
  and [wl-clipboard](https://github.com/bugaevc/wl-clipboard) for `scripts/capture`
- [playerctl](https://github.com/altdesktop/playerctl), `pactl`, `notify-send`
- Python 3 with numpy and Pillow (`scripts/gen-borders.py`)
- FantasqueSansM Nerd Font ([Nerd Fonts](https://www.nerdfonts.com/))

Hyprland plugins, installed with `hyprpm add <repository>` then
`hyprpm enable <plugin>`:

- `scrolloverview` — https://github.com/yayuuu/hyprland-scroll-overview
- `imgborders` — https://codeberg.org/zacoons/imgborders
- `borders-plus-plus` (optional, currently disabled) — https://github.com/hyprwm/hyprland-plugins

The DMS plugin recorded in `config/dms/plugins.lock.json` is downloaded again
by DMS; its files are not versioned. Do not run `dms setup`: it overwrites the
Hyprland configuration.

## qtile session

X11 session kept as a fallback. Software: [qtile](https://qtile.org/),
[picom](https://github.com/yshui/picom), [dunst](https://dunst-project.org/),
[rofi](https://github.com/davatorium/rofi),
[alacritty](https://github.com/alacritty/alacritty), playerctl, `pactl`,
`xrandr`.

`config/qtile/PyColors.py` is a link to the file wpg generates from
`config/wpg/templates/PyColors.py.base`.

Some keybindings:

- `Super + t` / `Super + e`: focus the primary / secondary display
- `Super + 1…5`: bring the workspace to the focused display
- `Super + Shift + 1…5`: send the focused window to the workspace
- `Super + j` / `Super + k`: next / previous window in the stack
- `Super + Space`: move the focused window to the main area
- `Super + Enter`: terminal

## Theme

[wpgtk](https://github.com/deviantfero/wpgtk) (on
[pywal](https://github.com/dylanaraps/pywal), with the haishoku, colorz,
colorthief and schemer2 backends), installed with pip.

`~/bin/theming-wpgtk.sh <wallpaper>` picks a backend, generates the palette and
fills the templates of `config/wpg/templates` (terminal sequences, qtile, rofi).
Under Hyprland it then runs `config/hypr/scripts/apply-theme.sh`: window
borders and frames are regenerated and the wallpaper is handed to DMS.
`zshrc` replays `~/.cache/wpg/sequences` in each new terminal.

## Zsh

`zshrc` is self-contained, without a plugin manager. Software:
[zsh-autosuggestions](https://github.com/zsh-users/zsh-autosuggestions),
[zsh-syntax-highlighting](https://github.com/zsh-users/zsh-syntax-highlighting),
[fzf](https://github.com/junegunn/fzf),
[zoxide](https://github.com/ajeetdsouza/zoxide),
[eza](https://github.com/eza-community/eza),
[bat](https://github.com/sharkdp/bat),
[ripgrep](https://github.com/BurntSushi/ripgrep) and
[nvm](https://github.com/nvm-sh/nvm). `ls`, `cat` and `grep` are aliased to
eza, bat and rg.

## Neovim

Plugins are managed by [lazy.nvim](https://github.com/folke/lazy.nvim), which
installs itself on first start; their versions are pinned in
`config/nvim/lazy-lock.json`. Plugin specifications are in
`config/nvim/lua/plugins`, language server settings in
`config/nvim/lua/config/lsp`. `:checkhealth` shows which language servers and
parsers are missing.

Other tools used from the editor or the terminal:
[lazygit](https://github.com/jesseduffield/lazygit), fzf, ripgrep, tmux.
